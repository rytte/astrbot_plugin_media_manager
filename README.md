# Media 管理

保留图片，减轻上下文占用，随时按需回看。

`astrbot_plugin_media_manager` 为 AstrBot 管理模型对话中的媒体资源。**当前版本支持图片**，包括原图归档、历史轻量化、按需回看、动图九宫格预览和群聊图片缓存；后续可扩展视频与音频。

## ✨ 功能亮点

| 能力 | 可以做什么 |
| --- | --- |
| 图片引用 | 回复结束后，将历史中的图片载荷替换为轻量引用，减少后续请求的上下文占用 |
| 动静态识别 | 自动检测并保存图片的动静态信息，在引用中标明静图、动图或动静态未知 |
| 原图回看 | 模型需要时，按引用重新查看当前会话中的图片 |
| 动图预览 | 为动图提供动画预览入口，按需为 GIF、WebP、APNG 生成最多九帧的 3×3 预览，附播放时长与采样说明 |
| 群聊图片缓存 | 缓存未被模型看过的群聊图片，支持“先发图、后唤醒”时按引用回看 |
| 工具图片归档 | 处理其他插件或 MCP 工具返回的多模态图片，保留工具文字说明 |
| 存储与清理 | 按平台、消息来源和 AstrBot 对话隔离引用，支持容量限制、到期清理与孤儿图片清理 |

> [!NOTE]
> **生成引用不会提前移除图片。** 本轮模型仍能直接看到图片；回复结束、AstrBot 保存历史前，才做替换。
>
> **图片引用适用于图片较多的情况**
>
> * 响应速度方面，图片总体积较大时会明显降低模型响应速度（相比于同样上下文长度的常规文本响应耗时会更长，经测试发现主要来自于更大的数据量，但无法验证其中多少属于网络传输、网关处理或服务端解析）。
> * token 开销与上下文占用方面，1280*1280 分辨率图片开销为 1600 tokens（OpenAI），替换为引用时，引用文本占用约 120 tokens，但是需要回看时调用工具获取到原图后会额外进行一次模型请求。因此在经常需要回看图片的情况下，未必节省 token。
> * 对应配置名为 `对话图片轻量化`。

## 🚀 快速开始

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.27,<5` |
| 模型 | 具有视觉能力和工具调用能力的模型 |
| 图片依赖 | `Pillow>=10.1,<14`，随插件安装时自动安装 |
| 群聊图片缓存 | 需在 AstrBot 中开启群聊上下文注入，平台需提供已下载的本地图片 |

插件使用 AstrBot 通用图片组件和 Agent 钩子。目前集成测试覆盖 OneBot QQ，其他适配器需结合其媒体预处理行为验证。

### 2. 安装插件

在 **AstrBot WebUI** 的插件市场页面中，搜索 `Media 管理` 或 `astrbot_plugin_media_manager` 安装。或直接从以下仓库安装：

```text
https://github.com/rytte/astrbot_plugin_media_manager
```

### 2. 启用并试用

在目标会话启用插件，按该会话的唤醒方式发送图片并与机器人对话：

| 场景 | 可以这样说 |
| --- | --- |
| 当前图片 | 发送图片后说：“帮我看看这张图。” |
| 历史图片 | “再看看刚才那张图的右下角。” |
| 动态表情 | “这张动图前后有什么变化。” |
| 先发图、后唤醒 | 在已开启群聊上下文注入的群里先发图，再唤醒机器人：“看看刚才那张图片。” |

模型会结合上下文和可用工具决定是否回看。

## 🖼️ 图片如何处理

1. **收到图片**：复制图片，检测并保存动静态信息，生成引用，保留本轮真实视觉输入。
2. **回复结束**：将待保存历史中的图片载荷替换为轻量引用。
3. **后续回看**：模型通过 `media_inspect` 加载图片，查看结果仅供本轮使用。

| 查看方式 | 工具参数 | 返回内容 |
| --- | --- | --- |
| 查看原图 | `view="original"` | 归档或缓存中的图片 |
| 查看动画 | `view="animation"` | 已确认的 GIF、WebP、APNG 动图最多九帧的九宫格与客观采样说明 |

工具调用示例

 ```
 media_inspect(image_ref="img_0123456abcdef", view="original")
 media_inspect(image_ref="img_0123456abcdef", view="animation")
 ```

`image_ref` 必须使用当前会话标签提供的真实引用，支持归档引用 `img_…` 与群缓存引用 `gimg_…`。动画预览复用原图引用，不覆盖原图，也不重复归档预览图片。

动静态由 Media 管理根据实际动画帧检测，不依赖文件扩展名或 QQ 语义。单帧 GIF、WebP 和只有一帧实际动画的 APNG 按静图处理，APNG 封面不计入动画帧。检测失败时标为“动静态未知”；**只有确认的动图才附动画预览入口**，静图和未知图片仍可查看原图。

## 🧩 图片 ID 协作

与 [QQ 能力增强](https://github.com/rytte/astrbot_plugin_qq_enhance) 一起启用时，两个插件通过相同的 `image_id=pic_…` 将 QQ 图片语义与媒体引用关联到同一次图片出现，模型应合并理解。`image_id` 仅用于关联，查看原图或动画预览仍使用 `media_inspect` 和真实的 `image_ref`；未启用 QQ 插件时，媒体引用可独立使用。

## ⚙️ 配置说明

插件启停统一使用 AstrBot 插件管理中的开关。具体功能在 AstrBot WebUI 的插件配置中调整，按以下四组展示。下表列出完整配置路径与默认值；容量单位均为 MiB。升级时会自动迁移旧版平铺配置，并将旧“私聊图片”开关和“原图归档”参数合并到“对话图片轻量化与归档”组，保留已有设置。

### 基础设置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `general.platform_ids` | `[]` | 适用的平台实例 ID；空列表表示全部 |

### 对话图片轻量化与归档

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `lightening.image_lighten_enabled` | `true` | **对话图片轻量化**：归档未进入群缓存的图片、生成引用并精简历史中的图片载荷 |
| `lightening.max_storage_mb` | `2048` | 长期归档总容量；不足时按最旧的本地自然日整日淘汰 |
| `lightening.retention_days` | `30` | 原图绝对保留自然日数；`0` 关闭绝对保留期，容量与孤儿清理仍生效 |
| `lightening.orphan_grace_days` | `3` | 引用从会话历史消失后的自然日宽限期；宽限期内重新出现会取消孤儿标记 |

该开关统一控制私聊图片、未进入群缓存但进入模型请求的群聊图片，以及其他插件或 MCP 工具返回图片的长期归档和历史轻量化。关闭后，这些图片按 AstrBot 原有方式保留，本插件不再为它们归档、生成媒体引用或移除图片载荷。

| 图片来源 | 开启对话图片轻量化 | 关闭对话图片轻量化 |
| --- | --- | --- |
| 私聊图片 | 长期归档，历史保存引用 | 保留 AstrBot 原有图片处理 |
| 已成功进入群缓存的群聊图片 | 使用群缓存引用 | 仍使用群缓存引用，独立控制 |
| 未进入群缓存、但进入模型请求的群聊图片 | 长期归档，历史保存引用 | 保留 AstrBot 原有图片处理 |
| 其他工具返回的图片 | 长期归档，历史保存引用 | 保留 AstrBot 原有图片处理 |

两种设置下，本轮实际进入模型请求的图片都能正常提供给模型。已成功缓存的群图片不会自动转为长期归档，仍遵循群缓存的容量和有效期；关闭轻量化不影响群缓存的收图、引用、历史精简和工具回看。

### 群聊图片缓存

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `group_cache.group_cache_enabled` | `true` | 缓存群聊图片，需开启 AstrBot 群聊上下文注入 |
| `group_cache.group_cache_max_mb` | `256` | 群缓存中唯一图片文件的总容量，与长期归档容量独立 |
| `group_cache.group_cache_ttl_hours` | `24` | 自最后收图起的有效期，查看不会续期 |

群缓存内置每条消息最多尝试缓存 **30 张图片** 的上限。按消息顺序处理，引用图片计入数量，缓存失败也占一个名额。**群聊图片关联标识全部分配；超出缓存数量且未复用已有缓存的图片，进入模型请求后由“对话图片轻量化”开关决定是否归档和精简历史。** QQ 插件自己的组件语义处理上限独立生效。

### 图片查看与清理

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `inspection.max_inspect_mb` | `10` | 单次查看的图片大小上限，同时限制群缓存的单张图片大小 |
| `inspection.disabled_views` | `[]` | 禁用指定查看方式：`original` 为原图，`animation` 为动画预览 |
| `inspection.cleanup_interval_seconds` | `600` | 清理检测间隔；归档图片的历史存活检查每个主机本地自然日最多一次 |

## 🛠️ 开发与验证

<details>
<summary>图片关联协议与钩子顺序</summary>

两个插件无需跨插件 Python 导入。共享协议键为 `event.extra["_image_context_links_v1"]`，值是当前事件内 `id(Image组件) -> pic_十六位十六进制` 映射。Python 对象 ID 不进入模型或数据库；重入时沿用已有映射。

绑定后的引用与消息字段随防抖序列化恢复，不依赖旧事件映射。优先级仅在同类钩子内比较，**高值先执行**，不依赖插件安装顺序。

| 钩子 | 优先级 | 顺序约束 |
| --- | --- | --- |
| 图片关联标识分配 | 消息事件 `1100` | 先于 QQ 语义 `1000` |
| 群图片复制、引用注入消息链 | 消息事件 `900` | 先于 AstrBot 群上下文记录 `0` |
| 请求归档与会话绑定 | `on_llm_request=-31000` | 晚于 QQ 续接重建 `-30000`，早于请求组装 |
| 绑定 `image_url.id` | `on_agent_begin=-19000` | 先于 QQ 防抖快照 `-20000`，仍保留图片载荷 |
| 历史轻量化 | `on_agent_done=-2000` | Agent 结束后、AstrBot 保存历史前 |

防抖只保存与恢复通用消息，不调用 Media 管理。

</details>

在可导入 AstrBot 且已安装 `pytest`、`pytest-asyncio` 的开发环境中运行：

```bash
python -m pytest -q
```
