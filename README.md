# Media 管理

保留图片，减轻上下文占用，随时按需回看。

`astrbot_plugin_media_manager` 为 AstrBot 管理模型对话中的媒体资源。**当前版本支持图片**，包括原图归档、历史轻量化、按需回看、动图九宫格预览和群聊图片缓存；后续可扩展视频与音频。

## ✨ 功能亮点

| 能力 | 可以做什么 |
| --- | --- |
| 图片引用 | 回复结束后，将历史中的图片载荷替换为轻量引用，减少后续请求的上下文占用 |
| 动静态识别 | 自动检测并保存图片的动静态信息，在引用中标明静图、动图或动静态未知 |
| 原图回看 | 模型需要时，按引用重新查看当前会话中的图片 |
| 动图预览 | 为动图提供动画预览入口，按需为 GIF、WebP、APNG 生成最多九帧的 3×3 预览，附播放时长与采样说明 |
| 群聊图片缓存 | 缓存已下载的群聊图片，支持“先发图、后唤醒”时按引用回看 |
| 工具图片归档 | 处理其他插件或 MCP 工具返回的多模态图片，保留工具文字说明 |
| 存储与清理 | 按平台、消息来源和 AstrBot 对话隔离引用，支持容量限制、到期清理与孤儿图片清理 |

> [!NOTE]
> **生成引用不会提前移除图片。** 本轮模型仍能直接看到图片；回复结束、AstrBot 保存历史前，才做替换。

## 🚀 快速开始

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.27,<5` |
| 模型 | 具有视觉能力和工具调用能力的模型 |
| 图片依赖 | `Pillow>=10.1,<13`，随插件安装时自动安装 |
| 群聊图片缓存 | 需在 AstrBot 中开启群聊上下文注入，平台需提供已下载的本地图片 |

插件使用 AstrBot 通用图片组件和 Agent 钩子。目前集成测试覆盖 OneBot QQ，其他适配器需结合其媒体预处理行为验证。

### 2. 安装插件

在 **AstrBot WebUI** 的插件市场页面中，搜索 `Media 管理` 或 `astrbot_plugin_media_manager` 安装。或直接从以下仓库安装：

```text
https://github.com/rytte/astrbot_plugin_media_manager
```

### 2. 启用并试用

在目标会话启用插件，按该会话的唤醒方式发送图片并与机器人对话：

| 场景 | 可以这样说 |
| --- | --- |
| 当前图片 | 发送图片后说：“帮我看看这张图。” |
| 历史图片 | “再看看刚才那张图的右下角。” |
| 动态表情 | “这张动图前后有什么变化。” |
| 先发图、后唤醒 | 在已开启群聊上下文注入的群里先发图，再唤醒机器人：“看看刚才那张图片。” |

模型会结合上下文和可用工具决定是否回看。

## 🖼️ 图片如何处理

1. **收到图片**：复制图片，检测并保存动静态信息，生成引用，保留本轮真实视觉输入。
2. **回复结束**：将待保存历史中的图片载荷替换为轻量引用。
3. **后续回看**：模型通过 `media_inspect` 加载图片，查看结果仅供本轮使用。

| 查看方式 | 工具参数 | 返回内容 |
| --- | --- | --- |
| 查看原图 | `view="original"` | 归档或缓存中的图片 |
| 查看动画 | `view="animation"` | 已确认的 GIF、WebP、APNG 动图最多九帧的九宫格与客观采样说明 |

工具调用示例

 ```
 media_inspect(image_ref="img_0123456abcdef", view="original")
 media_inspect(image_ref="img_0123456abcdef", view="animation")
 ```

`image_ref` 必须使用当前会话标签提供的真实引用，支持归档引用 `img_…` 与群缓存引用 `gimg_…`。动画预览复用原图引用，不覆盖原图，也不重复归档预览图片。

动静态由 Media 管理根据实际动画帧检测，不依赖文件扩展名或 QQ 语义。单帧 GIF、WebP 和只有一帧实际动画的 APNG 按静图处理，APNG 封面不计入动画帧。检测失败时标为“动静态未知”；**只有确认的动图才附动画预览入口**，静图和未知图片仍可查看原图。

## 🧩 QQ 插件配合与迁移说明

Media 管理插件由 [QQ 能力增强](https://github.com/rytte/astrbot_plugin_qq_enhance) 拆分而来，可以独立运行。与 QQ 能力增强插件一起使用时，QQ 插件提供图片类型、摘要及动态表情语义，Media 管理负责图片归档、引用、回看和清理。

### 独立标签，按图片关联

两个插件分别生成标签，通过相同的 `image_id` 关联同一次图片出现：

```text
[QQ component|QQ动态表情包：出发啦；image_id=pic_0123456abcdef]
[Media ImageRef image_ref=img_0123456abcdef, 320x240；动图；image_id=pic_0123456abcdef；查看入口…]
```

- 相同 `image_id` 表示同一次图片出现，模型应合并理解，不重复计数。
- 所有图片都会分配关联标识，引用消息中的图片也单独关联；QQ 只在可靠匹配且语义预算允许时附上该标识。
- `image_id` 用于标签关联，工具读取使用 `image_ref`。关闭 QQ 组件语义化后，媒体引用仍可独立使用。

### 从 QQ 能力增强迁移

> [!IMPORTANT]
> **先将 QQ 能力增强升级到 1.12.0 或以上，再启用 Media 管理。** 旧版 QQ 插件仍会管理图片，无法与 Media 管理同时处理图片。

1. 升级 QQ 插件，然后安装并启用 Media 管理。
2. 保持 `import_qq_enhance=true`，首次启动会导入旧图片设置、长期归档和群缓存。
3. 后续在 Media 管理中独立调整图片配置。QQ 保留的 `qq_media.inspect` / `inspect_animation` 会兼容转发到本插件，新引用使用 `media_inspect`。

QQ 的语义、防抖和其他 QQ 工具可独立运行；Media 管理未启用时，旧图片查看入口会明确返回能力不可用。

已有归档和仍有效的群缓存会自动补充动静态信息，保留原引用与有效期。新生成的引用包含检测结果，已保存的历史标签不批量改写。

<details>
<summary>迁移的数据、配置优先级与失败重试</summary>

旧数据来自 `data/plugin_data/astrbot_plugin_qq_enhance/`。迁移会保留原始引用、平台与会话绑定、创建及过期时间，复制文件并更新新索引中的路径。**源数据库和源文件保留用于回退。**

首次配置导入时，Media 管理已经设置的非默认值优先；其余继承旧图片配置。设置 `import_qq_enhance=false` 可跳过配置与数据导入。

成功导入会记录完成标识，后续重载不会重新导入已被清理的图片。迁移失败时，修复原因后重载即可重试；已缺失的源文件会计入日志，不生成虚假的可用引用。旧 `QQ ImageRef` 和 QQ 合并标签中的引用继续支持回看与历史存活检查。

</details>

## ⚙️ 配置说明

在 AstrBot WebUI 的插件配置中调整。下表列出配置键与默认值；容量单位均为 MiB。

### 基础设置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 启用图片归档、引用与查看工具 |
| `platform_ids` | `[]` | 适用的平台实例 ID；空列表表示全部 |
| `disabled_views` | `[]` | 禁用指定查看方式：`original` 为原图，`animation` 为动画预览 |
| `import_qq_enhance` | `true` | 首次导入 QQ 能力增强的旧图片配置和数据 |

### 原图归档

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `max_storage_mb` | `2048` | 长期归档总容量；不足时按最旧的本地自然日整日淘汰 |
| `retention_days` | `30` | 原图绝对保留自然日数；`0` 关闭绝对保留期，容量与孤儿清理仍生效 |
| `orphan_grace_days` | `3` | 引用从会话历史消失后的自然日宽限期；宽限期内重新出现会取消孤儿标记 |

### 群聊图片缓存

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `group_cache_enabled` | `true` | 缓存群聊图片，需开启 AstrBot 群聊上下文注入 |
| `group_cache_max_mb` | `256` | 群缓存中唯一图片文件的总容量，与长期归档容量独立 |
| `group_cache_ttl_hours` | `24` | 自最后收图起的有效期，查看不会续期 |
| `max_components` | `30` | **每条消息最多缓存图片数**，仅限制群缓存 |

`max_components` 沿用旧配置键以保留已保存的数值。按消息顺序处理，引用图片计入数量，缓存失败也占一个名额。**图片关联标识全部分配；超出缓存数量的图片，实际进入模型请求时仍会归档和轻量化。** QQ 插件自己的组件语义处理上限独立生效。

### 查看与清理

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `max_inspect_mb` | `10` | 单次查看的图片大小上限，同时限制群缓存的单张图片大小 |
| `cleanup_interval_seconds` | `600` | 清理检测间隔；归档图片的历史存活检查每个主机本地自然日最多一次 |

## 💬 常见问题

<details>
<summary>图片引用为什么有时无法查看？</summary>

群图片默认缓存 24 小时，也可能因容量不足提前淘汰。长期归档同样受容量、绝对保留期与孤儿清理规则约束，仍被历史引用的图片也可能达到容量或保留期限。

图片引用按平台实例、消息来源与 AstrBot 对话隔离。过期、被淘汰或不属于当前会话的引用，会明确返回不可用。

</details>

<details>
<summary>图片链接和工具返回的图片都会归档吗？</summary>

输入图片、引用消息图片，以及其他插件或 MCP 工具返回的多模态图片会参与归档。仅在普通文本中出现的图片 URL 不会作为图片附件处理。

群缓存只复制已经下载的本地图片，不会为未唤醒的消息额外下载图片或调用识图模型。

</details>

<details>
<summary>回复结束时归档失败，会丢失图片吗？</summary>

结束归档失败时会记录警告，并保留尚未归档的图片载荷。防抖补存的未回复输入也暂时保留完整图片，直到一次成功的结束轻量化。

</details>

## 🛠️ 开发与验证

<details>
<summary>图片关联协议与钩子顺序</summary>

两个插件无需跨插件 Python 导入。共享协议键为 `event.extra["_image_context_links_v1"]`，值是当前事件内 `id(Image组件) -> pic_十六位十六进制` 映射。Python 对象 ID 不进入模型或数据库；重入时沿用已有映射。

绑定后的引用与消息字段随防抖序列化恢复，不依赖旧事件映射。优先级仅在同类钩子内比较，**高值先执行**，不依赖插件安装顺序。

| 钩子 | 优先级 | 顺序约束 |
| --- | --- | --- |
| 图片关联标识分配 | 消息事件 `1100` | 先于 QQ 语义 `1000` |
| 群图片复制、引用注入消息链 | 消息事件 `900` | 先于 AstrBot 群上下文记录 `0` |
| 请求归档与会话绑定 | `on_llm_request=-31000` | 晚于 QQ 续接重建 `-30000`，早于请求组装 |
| 绑定 `image_url.id` | `on_agent_begin=-19000` | 先于 QQ 防抖快照 `-20000`，仍保留图片载荷 |
| 历史轻量化 | `on_agent_done=-2000` | Agent 结束后、AstrBot 保存历史前 |

防抖只保存与恢复通用消息，不调用 Media 管理。

</details>

在可导入 AstrBot 且已安装 `pytest`、`pytest-asyncio` 的开发环境中运行：

```bash
python -m pytest -q
```
